# Ubuntu Workstations v1.2.0 — release checklist

## Scope

- 31.1 weekly read-only mise, rustup, Docker and Proton update discovery.
- 31.2 GNOME notifications for available development updates.
- 31.3 explicit approval proposals for mise-managed Node.js updates.
- 31.4 explicit Docker/Proton APT package version review and simulated upgrade plans.
- 31.5 post-update Docker/Proton validation with path watcher and fallback timer.
- 31.6 read-only release readiness audit and declarative user lingering.

## On Omnissiah-desktop

1. Run full provisioning twice with `--limit desktop`; ensure second run reports `changed=0`.
2. Run strict validation playbook (`-e audit_enforce=true`).
3. Run `~/.local/bin/workstation-release-audit` and resolve any FAIL statuses.
4. Run `~/.local/bin/workstation-post-update-validate --watch`.
5. Test GNOME notifications in an actual GNOME session (`workstation-desktop-alerts --test-notification`). Run the failure/recovery smoke test below.
6. Inspect the git diff and staged files for credentials or generated state before committing.
7. Commit, push, verify `HEAD` and `origin/main` agree, then create and push an annotated `v1.2.0` tag.

## Limitations / follow-up

- User lingering keeps systemd user units alive while logged out, but it does not create an active GNOME graphical session. GNOME notification delivery still requires login.
- The release audit checks service/timer state, report presence, and reported overall status, but does not assess report freshness. Inspect timestamps and underlying reports separately.
- Post-update validation failures are now read by the existing GNOME alert pipeline (30-minute timer, 24-hour duplicate suppression). The validator writes reports on validation runs only; absent or old *successful* reports do not generate an alert. An actual failed report persists until a successful validation replaces it.
- A successful `--watch` with unchanged versions does not overwrite a prior failure report. After a confirmed repair, rerun `workstation-post-update-validate --check all` to clear that failure.
- Proton VPN package validation does not prove the VPN is connected or authenticated.
- Proton Drive backup success timestamps do not replace periodic remote restore tests.
- Drift monitoring currently checks selected files, not the complete installed system.
- Avoid manually modifying the drift monitor's managed baseline except for controlled tests that always restore it.

## Post-update alert integration smoke test

1. Deploy the updated `desktop_alerts` role and confirm idempotency.
2. Run `workstation-post-update-validate --check all` and confirm it reports HEALTHY.
3. Run `workstation-desktop-alerts --dry-run`; it should not report a post-update issue.
4. Run `workstation-desktop-alerts --dry-run --test-post-update-failure`; it must show an attention item for Post-update validation and a proposed notification. This changes no report or notification state.
5. Run `workstation-desktop-alerts --test-notification` to verify actual GNOME delivery.

Notifications are best-effort while a graphical GNOME session is available; a missed delivery should not be marked sent.
